# EXP_R9 execution log

The first tournament attempt stopped before development/held-out evaluation when the historical matched-refinement F2 was called inside `torch.no_grad()`. Its internal energy step differentiates with respect to the candidate, so PyTorch raised `element 0 of tensors does not require grad`. No held-out result was read and no claim was made. The implementation was corrected to keep F1 inference in `no_grad` while wrapping historical F2 calls in `torch.enable_grad`, then the registered run was restarted without changing data, splits, candidates, or thresholds.

The corrected run then exceeded the practical CPU time budget in repeated graph/CEM/trajectory replans before writing metrics. It was stopped without reading held-out results. The same registered candidates were retained, but the implementation now skips train-only evaluation cases after proposal fitting, uses a deterministic train-support stride for graph/CEM costs, uses a fixed low-cost CEM budget, and uses four optimization steps for the trajectory candidate. These are computationally equivalent candidate families with explicit budgets, not a change to the data split or claim threshold.
